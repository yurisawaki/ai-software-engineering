# Aula __ (01/09)
**Projeto open Source** Ieducar
**Pull Request Analizado** https://github.com/portabilis/i-educar/pull/1103
**Objetivo.** Refazer, sem ver o patch, o PR já mergeado da issue #1060 (validação de CEP no cadastro de pessoa física) e comparar com o que foi realmente aceito.
**Ferramenta.** Claude (chat), sem acesso ao repositório — só a descrição do bug e o código atual.
**O que o agente entregou.** Lógica igual ao PR mergeado (bloqueio local de CEP repetido antes da request, 404 separado de erro genérico, mesmas 4 mensagens de texto), mas com regex de formato ancorada (`^\d{5}-\d{3}$`) e um elemento de erro genérico inventado, por não conhecer o HTML/CSS reais.
**O que mudamos à mão.** Trocamos o erro genérico pela classe `.error` + `.postal-code-error-message` que o PR mergeado já usa (era o padrão real do projeto). Mantivemos, porém, a regex ancorada do agente: testamos a regex do PR mergeado (`/[0-9]{5}-[0-9]{3}/`, sem `^$`) contra os casos do próprio issue e `12345-6789` e `12345-678abc` passam na validação e chegam a chamar a API — exatamente o que o issue pedia para bloquear.
**O que aprendemos.** Sem repo, o agente inventa a UI mas não erra a validação; com repo, o revisor humano acertou a UI mas deixou passar um bug de regex que uma checagem automatizada simples pegou na hora.
